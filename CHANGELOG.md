- Анализатор инструментов (T5, `src/server/ai/tool-analyzer.ts`): анализ страницы, чат по карточке и подбор под задачу; чужой текст только внутри ограничителей и обезвреженный (NFKC, невидимые символы, `<` `>`), цитаты ограничений сверяются с текстом страницы, ответ модели обрезается по лимитам; мок-LLM понимает анализ инструмента и подбор; тесты и тесты безопасности.
- Серверная часть раздела «Инструменты» (T6): общая очередь фоновых задач `JobQueue` (анализ репозиториев переведён на неё без изменения поведения), `ToolsService` (добавление по ссылке и вручную — ручная карточка сразу подтверждена, обновление страницы, анализ, своя картинка, дедупликация по адресу и по адресу после редиректа в обе стороны), `isAnalysisStale` для признака «источник новее анализа», маршруты `/api/tools*` на строгих схемах (адрес до 2000 символов), отдача `/tool-images/` с `nosniff` и `CSP: sandbox` (имена файлов картинок проверяются по формату `id` и границе папки, удаление — только по точному шаблону имени), `tools` в `/api/health`, прокси `/tool-images` в Vite, проверки в smoke, тесты `tools-api` и тесты безопасности.
- Чат по карточке инструмента и подбор под задачу (T7, `POST /api/tools/:id/chat`, `POST /api/tools/recommend`): чат отвечает по карточке и сохранённому тексту страницы и честно предупреждает, если текста нет или он неполный; заметки пользователя уходят в модель отдельным блоком `<<<ЗАМЕТКИ` / `ЗАМЕТКИ>>>` не длиннее 8000 символов; подбор через LLM принимает только карточки, реально показанные модели (длинная карточка пропускается, а не обрывает каталог), без LLM или при её сбое — поиск по словам; тесты и тесты безопасности.
- Экспорт и импорт библиотеки версии 2 включают инструменты вместе с картинками (T8): файл версии 1 по-прежнему читается; дубликаты при импорте ищутся по ключу адреса; новые записи получают локальный `id`, пути картинок строятся из него, а не берутся из файла; тип картинок — по белому списку загрузчика (включая `.ico` и `.svg`); файлы картинок записываются и удаляются только после успешной транзакции, откат не оставляет сирот и не портит локальные картинки.

- Раздел «Инструменты» в интерфейсе (T9): пункт «Инструменты» в навигации и поиске шапки, каталог `/tools` с карточками, фильтрами (категории, теги, избранное, черновики, без AI-анализа) и сортировкой в адресе страницы, диалог добавления по ссылке с ручной карточкой при сбое загрузки или на локальный адрес и подсказкой для ссылок на репозитории GitHub, реплики маскота, блок инструментов в предпросмотре и результате импорта; шапка переходит в две строки до 1100 px и не переполняет экран на 320–390 px.
- Карточка инструмента `/tools/:id` (T10): правка названия и описания на месте, плашка черновика и подтверждение, AI-сводка в четырёх статусах с пометкой «анализ устарел», правка любого поля сводки поверх AI с показом и возвратом версии AI, категория (с клавиатуры сохраняется по Enter или уходу фокуса), теги, заметки, своя картинка, обновление страницы с понятным текстом для внутренних адресов, удаление с подтверждением; сбой фонового обновления не теряет открытые правки; общие функции `toolAiField`, `isDescriptionOverridden` в `src/shared/tools.ts`.
- Чат по карточке инструмента у маскота и «Подобрать под задачу» в каталоге (T11): общий компонент чата с репозиториями (история каждого инструмента отдельно, история репозиториев не изменилась), ответы без картинок и форм, панель подбора с причиной и меткой соответствия, режимом «поиск по словам» и задачей в `?task=`, компактные карточки в подборе; заметки инструмента не переписывают относительные ссылки и не загружают картинки.
- Страница приложения в production отдаётся с `Content-Security-Policy` (T17): хеш встроенного скрипта темы считается из `index.html` (с нормализацией переводов строк, как в браузере), `connect-src`/`form-action`/`script-src` только свои, без внешних таблиц стилей; и с `X-DNS-Prefetch-Control: off` — второй слой к очистке Markdown; на `/api/*`, `/avatars/`, `/tool-images/` политика не ставится; тесты `app-headers` и тесты безопасности, проверка в `npm run smoke`.

### Changed
- Правило `.claude/rules/data-safety.md` (локально): `user.imagePath` инструмента меняется только через `PUT /api/tools/:id/image` → `applyToolImage`, а не через `PATCH`.
- Вызов LLM вынесен в `src/server/ai/llm.ts`; `analyzer.ts` реэкспортирует `extractJson` и `probeLlm`, поведение анализа и чата репозиториев не изменилось.

### Fixed
- Очистка Markdown в три уровня: тег и атрибут `style` запрещены везде (включая README — чужой CSS больше не перекрашивает приложение и не грузит `@import`), заметки инструмента — без внешних загрузок, текст модели — ещё без форм, `id` и `class`; на месте вырезанной картинки — «[картинка скрыта]».
- Фильтры каталога инструментов передаются повторяющимися параметрами (`?tags=a&tags=b`), поэтому категория или тег с запятой фильтруются правильно; ручная карточка на локальный адрес создаётся без загрузки страницы (тест).
- Сервер больше не падает, если репозиторий удалили, пока шёл его AI-анализ: очередь пропускает запись и продолжает работу.
- «Обновить с GitHub» больше не затирает заметки, статус и AI-анализ, изменённые пока шёл запрос к GitHub; два одновременных добавления одного репозитория дают «уже в библиотеке», а не внутреннюю ошибку.
- Защита от DNS rebinding: при прослушивании `127.0.0.1` сервер отвечает 403 на запросы с чужим заголовком `Host`, так что чужая страница не может прочитать библиотеку или подменить адрес LLM, чтобы получить ключ.
- Ответы чата о репозитории больше ничего не загружают сами (картинки, медиа, `url()` в стилях): подсказка из чужого README не может заставить модель вставить картинку, адрес которой унесёт текст разговора. README и заметки показываются как раньше.
- `POST /api/repos/:id/analyze?wait=1` запускает анализ один раз, а не дважды (очередь плюс прямой вызов).
- Импорт со стратегией «пропустить» и «объединить» больше не перезаписывает локальный файл аватара картинкой из файла импорта.
- Ключ LLM больше не может попасть в сообщение об ошибке анализа (а с ним в базу, интерфейс и экспорт), если сервер LLM повторяет его в теле ответа; логин и пароль в адресе LLM в сообщениях об ошибках скрываются.
- Workflow App: задание smoke на Intel Mac не находило архив — артефакт `gitlib-macos` сохраняет папку версии (`release/<версия>/`), а распаковка искала zip в корне `release/`.

## [1.1.0] — 2026-10-29

### Added
- Файл `LICENSE` (Apache License 2.0) из репозитория github.com/sateevvk-blip/GitLib; проект опубликован там, история слита с первым коммитом репозитория.
- Правило релизов `.claude/rules/release.md`: каждый выпуск со своим номером SemVer, артефакты `npm run bundle` / `npm run bundle:app` — в подпапке `release/<версия>/`, папки прошлых релизов не перезаписываются; навык `gitlib-release` дополнен этим шагом.
- Заметки в Markdown: на странице репозитория заметка показывается отформатированной (заголовки, списки, чек-листы, ссылки, код — через `marked` + DOMPurify, одиночные переносы строк сохраняются), клик по тексту или кнопка «Править» открывает редактор. В редакторе панель форматирования (жирный, курсив, зачёркнутый, код, заголовок, списки, чек-лист, цитата, ссылка, блок кода), горячие клавиши Ctrl+B / I / E / K, Enter продолжает список (пустой пункт завершает его), Ctrl+Enter или Esc возвращает в просмотр, поле растёт по содержимому. Чек-боксы в просмотре переключаются кликом и сохраняются в текст; относительные ссылки ведут в репозиторий. Чистые функции `src/client/lib/markdown-edit.ts`, тесты `tests/markdown-edit.test.ts`.
- Чат о репозитории читает его файлы, а не только README: перед ответом сервер берёт дерево файлов ветки по умолчанию (`GET /git/trees/:branch?recursive=1`), отбирает кандидатов по ключевым словам вопроса (русские корни «команд», «скилл», «установ»… переводятся в фрагменты путей, переводы документации вроде `docs/ja-JP/` и скрытые папки уходят вниз, корневой README исключается — `rankFiles` в `src/server/ai/context.ts`), просит модель выбрать до 8 файлов (`selectChatFiles`, JSON-режим; при сбое — кандидаты по эвристике), читает их по sha блоба и отдаёт модели вместе со сводкой структуры (служебные папки, бинарные, lock-файлы и файлы крупнее 300 КБ не читаются; бюджет 14 К символов на дерево, причём папка, совпадающая с вопросом, например `commands/`, показывается целиком; 10 К на файл, 40 К на все). Новый системный промпт: отвечать по содержимому файлов, перечислять конкретные команды/скиллы/примеры по именам, называть файлы по пути и завершать практическим советом по применению. Ответ `POST /api/repos/:id/chat` содержит `sources` (прочитанные пути — в окне чата показываются ссылками на GitHub) и `notice` (GitHub недоступен, лимит запросов). Структура и файлы кэшируются в SQLite (`repo_trees`, `repo_files`, схема v2, удаляются вместе с записью); без сети используется сохранённое, без кэша — ответ по README с пометкой. Новые подсказки-вопросы «Как это устроено внутри?» и «С чего начать и как применить у себя?», мок `scripts/mock-llm.mjs` отвечает и на выбор файлов. Тесты `tests/chat-context.test.ts`.
- Чат о репозитории, который открывает маскот: на странице репозитория у маскота появляется значок «?», клик по нему открывает окно чата над напарником (Esc или повторный клик закрывает). Вопросы уходят в `POST /api/repos/:id/chat` вместе с историей (последние 20 реплик); модель получает метаданные, README и готовую сводку (`buildChatMessages` в `analyzer.ts`), отвечает по-русски с Markdown. Подсказки-вопросы для старта, повтор при ошибке, очистка разговора; история хранится в браузере на сессию вкладки (`sessionStorage`), запись в библиотеке не меняется. Без настроенной LLM чат показывает ссылку на настройки, без сети — ввод недоступен. Маскот думает, пока ждёт ответ, радуется ответу и «кружится» при ошибке; один раз за сессию приглашает задать вопрос. Мок `scripts/mock-llm.mjs` отвечает и на чат. Тесты `tests/chat.test.ts` и `tests/api.test.ts`.
