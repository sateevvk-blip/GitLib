# GitLib — персональная библиотека GitHub-репозиториев

Локальное веб-приложение для ежедневного использования. Вставляете ссылку на репозиторий — GitLib забирает
метаданные и README с GitHub, составляет русскоязычную сводку (что это, зачем нужно, когда пригодится)
через любой OpenAI-совместимый API и кладёт проект на полку. Дальше — поиск (в том числе по-русски),
фильтры, личные заметки, темы, коллекции и статусы изучения. Всё хранится локально, библиотека работает офлайн.

За порядком следит маскот Том — том книги в кобальтовой обложке. Он спит, пока библиотека пуста, читает README,
когда вы добавляете проект, радуется избранному и грустит, если пропала сеть.

## Возможности

- **Добавление** по `https://github.com/owner/repo`, `owner/repo`, `git@github.com:owner/repo.git` и другим формам; дубликаты отклоняются без учёта регистра, учитывается переименование репозитория на GitHub.
- **Данные GitHub**: описание, звёзды, форки, issues, лицензия, языки, topics, README, аватар владельца (сохраняется локально). Обновление по кнопке.
- **AI-анализ**: сводка на русском, практические сценарии, предложенные темы. Любой OpenAI-совместимый эндпоинт (OpenAI, OpenRouter, Ollama, LM Studio, vLLM…), ключ не обязателен. Без настроенной LLM приложение честно показывает «AI-анализ отсутствует». Сбой анализа не мешает сохранению, анализ можно повторить.
- **Поиск и фильтры**: регистронезависимый поиск с кириллицей и «ё» по имени, описанию, темам, сводке, сценариям и заметкам; комбинируемые фильтры по темам, языкам, статусам, избранному, коллекциям; сортировки; состояние фильтров живёт в URL.
- **Личное**: заметки с автосохранением, свои темы плюс темы GitHub и предложения AI, статусы «Входящие / Хочу попробовать / Использую / Отложено», избранное, коллекции.
- **Сохранность**: пользовательские данные лежат отдельно от загруженных и сгенерированных — обновление с GitHub или повторный анализ их не трогают.
- **Перенос**: экспорт в JSON с версией формата (включая README и аватары), импорт с валидацией, предпросмотром и понятными стратегиями для дубликатов.
- **Интерфейс**: светлая и тёмная темы, состояния загрузки / ошибок / пустой библиотеки, офлайн-индикатор, клавиша `/` для поиска.

## Требования

- Node.js **22.13 или новее** (используется встроенный `node:sqlite`; нативных модулей нет).
- npm 10+.
- Для получения новых репозиториев — доступ к `api.github.com`; для AI-анализа — доступ к выбранному LLM-эндпоинту. Для просмотра, поиска и правок сеть не нужна.

## Быстрый старт

```bash
npm install
npm run build
npm start
```

Откройте <http://localhost:4817>. Данные появятся в папке `data/` рядом с `package.json`.

Режим разработки с горячей перезагрузкой (сервер на 4817, Vite на 5173 с прокси `/api` и `/avatars`):

```bash
npm run dev
```

## Настройка интеграций

Всё настраивается на странице **Настройки** в приложении и сохраняется в `data/settings.json`.
Переменные окружения задают значения по умолчанию; непустое значение из настроек имеет приоритет.
Пример — в `.env.example`.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `GITLIB_PORT` | порт HTTP-сервера | `4817` |
| `GITLIB_HOST` | адрес прослушивания | `127.0.0.1` |
| `GITLIB_DATA_DIR` | папка с данными | `./data` |
| `GITLIB_LOG_LEVEL` | уровень логов (`info`, `warn`, `error`) | `info` |
| `GITHUB_TOKEN` | токен GitHub | — |
| `LLM_BASE_URL` | базовый URL OpenAI-совместимого API | — |
| `LLM_MODEL` | имя модели | — |
| `LLM_API_KEY` | ключ API | — |
| `LLM_TIMEOUT_SEC` | таймаут запроса к модели, секунд | `120` |

### GitHub

Без токена GitHub даёт 60 запросов в час на IP (одно добавление — 3 запроса), с токеном — 5000.
Создайте fine-grained token с доступом только к публичным репозиториям и вставьте его в «Настройки → GitHub».
Кнопка «Проверить подключение» показывает остаток лимита.

### AI-анализ

В «Настройки → AI-анализ» укажите Base URL и модель. Запросы идут на `{Base URL}/chat/completions`.

| Провайдер | Base URL | Модель (пример) | Ключ |
|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | нужен |
| OpenRouter | `https://openrouter.ai/api/v1` | `anthropic/claude-3.5-haiku` | нужен |
| Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` | не нужен |
| LM Studio | `http://localhost:1234/v1` | как в LM Studio | не нужен |

Если эндпоинт не поддерживает `response_format: json_object`, GitLib автоматически повторит запрос без него.
Модели до 7B могут иногда возвращать невалидный JSON — тогда статус анализа станет «не удался», и его можно повторить кнопкой.

Для проверки без настоящей модели есть мок: `node scripts/mock-llm.mjs` (Base URL `http://localhost:4899/v1`, модель `mock-1`).

## Где лежат данные

Папка `data/` (или `GITLIB_DATA_DIR`):

| Файл | Что это |
|---|---|
| `gitlib.sqlite` (+ `-wal`, `-shm`) | база: репозитории, README, анализ, заметки, коллекции |
| `avatars/` | аватары владельцев (`owner.png` / `.jpg`) |
| `settings.json` | токен GitHub, параметры LLM (права `0600`, в экспорт не попадает) |

Путь к папке показывается в «Настройки → Данные».

## Резервное копирование и восстановление

**Способ 1 — копия папки.** Остановите сервер и скопируйте папку `data/` целиком (включая `-wal`-файл, если он есть).
Восстановление: остановите сервер, верните папку на место (или укажите её в `GITLIB_DATA_DIR`), запустите.

**Способ 2 — экспорт в JSON.** «Настройки → Данные → Экспорт библиотеки в JSON» (или `GET /api/export`).
Файл `gitlib-<дата>.json` содержит все записи с README, аватары, заметки, темы, статусы, избранное и коллекции — версия формата внутри.
Восстановление или перенос на другой компьютер: «Импорт из JSON» → предпросмотр покажет, сколько записей новых и сколько уже есть →
выберите, что делать с дубликатами:

- **Объединить** (по умолчанию) — заметки склеиваются с разделителем, темы объединяются, избранное и статус не понижаются, данные GitHub и AI берутся более свежие. Ничего не теряется.
- **Пропустить** — существующие записи не трогаются, добавляются только новые.
- **Заменить** — версия из файла полностью перезаписывает локальную, включая заметки. Необратимо, об этом предупреждает интерфейс.

Коллекции сопоставляются по названию без учёта регистра и объединяются по составу.

## Офлайн

Сохранённая библиотека полностью доступна без сети: просмотр, поиск, заметки, темы, статусы, коллекции, экспорт и импорт.
Шрифты и иконки упакованы в сборку, аватары лежат локально. Без сети недоступны только добавление новых репозиториев,
обновление с GitHub и AI-анализ — соответствующие кнопки блокируются, а Том сообщает об офлайне. Картинки внутри README,
ссылающиеся на внешние адреса, без сети не загрузятся.

## Поделиться приложением

`npm run bundle` собирает production-версию и упаковывает её в `release/<версия>/gitlib-<версия>.zip` (≈6 МБ; у каждого выпуска своя подпапка, прошлые не перезаписываются):
собранный клиент и сервер, серверные зависимости (`node_modules` уже внутри, без тестов и примеров),
скрипты запуска и `README.md` с инструкцией для получателя. Получателю нужен только Node.js 22.13+:
распаковать и запустить `GitLib.cmd` (Windows), `GitLib.command` (macOS) или `sh gitlib.sh` (Linux) —
откроется браузер, данные лягут в `data/` внутри распакованной папки. Повторный запуск при уже работающем
GitLib просто открывает его. `npm run bundle -- --skip-build` упаковывает уже собранный `dist/`.
Шаблоны лаунчеров и инструкции — в `scripts/bundle/`.

## Структура проекта

```

src/server/    Fastify: маршруты, сервис библиотеки, SQLite-хранилище, GitHub-клиент, AI-анализатор, экспорт/импорт
src/client/    React: страницы, компоненты, маскот, API-хуки, стили

scripts/       smoke.mjs, mock-llm.mjs
.claude/       обвязка для Claude Code: правила, агенты, навыки, конфигурация запуска
.github/       CI: typecheck, тесты, сборка, smoke на Linux и Windows
```

## API

Все маршруты под `/api`, JSON. Основные: `GET/POST /repos`, `GET/PATCH/DELETE /repos/:id`, `POST /repos/:id/refresh`,
`POST /repos/:id/analyze[?wait=1]`, `GET /facets`, `GET/POST /collections`, `PATCH/DELETE /collections/:id`,
`POST /collections/:id/repos`, `DELETE /collections/:id/repos/:repoId`, `GET/PUT /settings`, `POST /settings/test/{github,llm}`,
`GET /export`, `POST /import/preview`, `POST /import?strategy=merge|skip|replace`, `GET /health`.

## Известные ограничения

- Сервер слушает только `127.0.0.1` и не имеет аутентификации — он рассчитан на один компьютер. Для доступа из сети задайте `GITLIB_HOST`, но помните, что настройки с токенами доступны любому, кто откроет приложение.
- README хранится обрезанным до 200 000 символов; модели передаются первые 14 000.
- Встроенный `node:sqlite` помечен в Node 22 как экспериментальный; предупреждение подавляется флагом в `npm start`.
- Поиск — подстрочный по словам (все слова должны встретиться), без морфологии и опечаток.
- Приватные репозитории доступны только с токеном, у которого есть к ним доступ.
